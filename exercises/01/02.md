# Why Keep an Interpreter After You Have a Compiler?

A compiler toolchain initially uses an interpreter for an intermediate representation (like P‑code). Even after creating a native code compiler, explain why this interpreter is still valuable.

---

1. Correctness
   The P-code compiler and interpreter provide a well-tested reference implementation. A new machine-code compiler could be tested and validated by compiling the same program and checking the result against the reference.
2. Easier debugging
   P-code is small, simple, and machine independent. It is far easier to reason about and debug than real machine code. Based on this, the author could compare their implementation against the P-code instructions and locate where the issue is.
3. Portability
   Retaining the P-code interpreter and compiler written in P-code makes porting to new machines with new architectures trivial as rewriting the P-code interpreter for the new target machine is not a very difficult task. This way the compiler and all Pascal programs can remain unchanged. This was especially valuable in 1970s-80s when architectures changed rapidly.
