# 1.7 Integer Size, Overflow, and Portability Across Languages

For the version of C available on your system, report the typical sizes of integer types. Describe what happens when arithmetic overflow occurs. Explain how implementation‑dependent integer sizes affect portability. Then compare these behaviors with several other languages (e.g., Java, Ada, Pascal, Scheme), focusing on integer size rules and overflow semantics.

---

## C

The size of the integer is not defined by CPU architecture alone. It is defined by C standard and compilers minimum guarantees.

```txt
int         32 bits
long        64 bits (mac and linux) 32 bits (windows)
long long   64 bits
```

For an overflow, most hardware wraps around but the C compiler explicitly states that it will result in an undefined behavior. This behavior could break codes that assume fixed sizes for different devices and machines.

## Java

Java avoids the portability issue by fixing the sizes in the standard.

```txt
byte     8 bits
short    16 bits
int      32 bits
long     64 bits
```

An overflow results in a wrap around (MAX_INTEGER will become MIN_INTEGER).

## Ada

Ada has range-constrained types.

```ada
type Small_Int is range 0 .. 100;
```

For overflows, Ada raises an error.

## Pascal

Pascal is heavily dependent on its implementation.

## Scheme

Scheme integers are usually arbitrary precision (bignums). These numbers can expand beyond machine limitations, so typically an overflow does not happen.
